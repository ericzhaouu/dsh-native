PER-AGENT SKILL VISIBILITY OVERRIDE (0.5.2)

taskPreparation.skillAllowlistByAgent is optional. Keys must be exact IDs that
also appear in taskPreparation.agentIds. Each value uses the same exact Skill
name validation as skillAllowlist, max 12, no wildcards or duplicates. A listed
Agent's array REPLACES shared skillAllowlist; [] explicitly advertises none.
Omitted Agents inherit the shared list. This only changes visible Skill
instructions for preparation; it does not install tools, change auth, connect
MCP or alter the child protocol.

  {
    "taskPreparation": {
      "agentIds": ["dsh-experiment", "dsh-other"],
      "skillAllowlist": [],
      "skillAllowlistByAgent": {
        "dsh-experiment": ["content-distill"],
        "dsh-other": []
      }
    }
  }

SAME-SESSION RESET REPAIR (0.5.1)

The host's chat /new can keep sessionId and append a clear-context reset event.
Visible history is retained; a new session ID is not guaranteed. The adapter uses
the authoritative active-branch clear boundary for context and native-state
isolation, preserving old transcript/state, full user admission and host identity.
Reset-looking message text is not authority to import or discard runtime history.
Unclear, retained-tail or concurrent conflicting boundaries still fail closed.
This does not add search, channel business tools or proactive delivery permissions.

HOST TOOL NARROWING (0.5.0)

Configure toolAllowlist with up to 64 unique exact host tool names, for example
["read", "web_search", "web_fetch"]. OpenClaw must already provide and authorize
them. An empty list exposes no tools. Missing configuration keeps legacy defaults.
No wildcard or private bridge control names are accepted.

OpenClaw owns tool construction, credentials, policy, approvals, transport and
cleanup. DSH chooses from the narrowed compatible instances and calls them back
through the host. This is not a new tool lifecycle/connection platform.
Core web_search continues using the host's configured search provider.

The top-level list works without adaptive preparation. When preparation is enabled,
omit its legacy executionTools field to derive the ceiling from toolAllowlist.
Explicit conflicting lists are rejected, not silently merged or widened.
See examples\openclaw.host-tools.json.

Missing, filtered, ambiguous or incompatible requested tools are explained without
guessing secret/config causes. They are capability gaps, not endless clarification
questions. An absent dedicated business-tool name does not itself deny an existing
host-authorized CLI route, nor does an unavailable-or-denied notice authorize one.
Only an actually exposed exec callback, task authorization and existing host
permissions/approvals permit CLI use. Never evade explicit denial by installing
capabilities, creating credentials/connections, switching accounts or dispatchers.
Only compatible text results cross the bridge; raw details/auth/transport metadata remain host-side.
Standard plugin/channel tool instances retain their source and host policy.
Unlisted plugin factories may still initialize during host construction; narrowing
constrains exposure/execution, not a sandbox around installed native plugin code.
No universal live requester-MCP, special approval continuation, media/browser,
messaging/cron/delegation or nested Tool Search/Code Mode compatibility is claimed.
Skills remain methods and their visible allowlist does not grant execution tools.

ADAPTIVE TASK PREPARATION (0.4.0, DEFAULT OFF)

Optional taskPreparation configuration applies only to exact agentIds.
Chat/clarify/draft modes have no host tools; execute gets the intersection of
executionTools and current host permissions. No model decision grants new authority.
Skill catalog descriptions are not loaded full instructions. Non-execution modes
cannot read missing Skill bodies or claim full method adherence unless those
instructions are already in approved context.
One first-step dsh_prepare_task control call is validated by the parent before
any host tool can become available. Decision and execution cannot be batched in
the same model response. Preparation text/reasoning stays out of visible replies,
but its usage and native decision record remain part of the private session.

Defaults: agentIds=[], skillAllowlist=[], maxClarificationTurns=3 (1..5),
maxToolCalls=24 (1..100 per attempt). Without toolAllowlist, legacy executionTools
defaults to the core coding family and can only narrow what the host provides. Every enabled turn
normally adds a model decision step; this is not zero-cost intent classification.
See examples\openclaw.task-preparation.json and the complete Chinese README.

The original user message is retained. Compact task state is versioned and
committed with the existing private binding after successful native settlement.
Each turn recomputes its gate. Changing policy or toggling preparation on an
existing session requires /new; corrupt/uncertain state never falls back to
unrestricted execution. Reaching the clarification limit produces an unresolved
draft, not mandatory execution. Only explicit skillAllowlist entries are advertised.
skillAllowlistByAgent can replace that shared list for one enabled Agent without
changing another. Listing a skill is not a guarantee its dependencies or tools
are supported.

Natural-language intent classification can be wrong. Opt-in permits automatic
handling of sufficiently clear requests within the configured ceiling; it is not
a semantic authorization proof or an exec/network sandbox. Keep host approval
rules. Remove exec/process from the ceiling when arbitrary programs are unwanted.
External services are usable only through admitted host tools. The bridge does not
install services, add privileges or bypass unavailable capabilities.

RETAINED 0.3.1 FIXES

Current-attempt attribution uses the validated executing provider/model instead
of redacted transcript identity. Canonical content and redaction remain intact.
The public assistant event publishes one approved final snapshot after persistence,
cleanup and the awaited agent_end hook barrier, so Dashboard receives real text.
Existing partial callbacks remain; this does not promise per-token Dashboard text.
Ownership is retained through publication; cancelled, reset, disposed and failed
attempts do not publish a successful final. SDK best-effort hook error policy remains.
Real Gateway tests inspect delivered agent/chat events, not only chat.history,
including redacted metadata, tools, continuation and stock-host compatibility.
The 0.3.0 host-patch specification is unchanged. Version 0.3.1 did not support
isolated completions; see the 0.6.0 support below. Install in a maintenance
window and start /new; old history/notices are not rewritten or deleted.

WHAT THIS IS

A native OpenClaw AgentHarnessV2 plugin, NOT an ACP target or model provider.
OpenClaw prepares the current/default model, authentication, workspace and
policy-bound coding tools. Official DSH runs one model/tool-loop attempt in a
child process, connected by private piped JSON-RPC. Model-callable tools return
to OpenClaw callbacks and its policy/approval/execution hooks.

DSH's own shell/editor/filesystem tools and stock SDK server are disabled;
ambient MCP, subagents and product integrations are not enabled. The effective
tool catalogue is audited. No acpx, separate global DSH installation, DSH web
server or model-weight download is required.

This is TRUSTED NATIVE CODE, not an OS sandbox. Merely enabling the plugin does
not auto-select it or replace other Agents' runtimes.

SUPPORTED BASELINE

- Node.js: >=22.23.1 <23 || >=24.15.0. Node 23 is not included.
  Historical actual testing includes Linux Node 22.23.1. Some tests import
  TypeScript directly and use type stripping and node:module.registerHooks.
  Native Windows uses node.exe with structured subprocess argv; this is not a
  claim that every platform/Node combination has been rerun.
- Exact official OpenClaw 2026.9.2 experimental AgentHarnessV2 SDK artifact.
  Declared pluginApi/optional-peer range >=2026.9.2 <2026.10.0 does not prove
  every build in that range compatible. Do not substitute "latest".
- DSH package group pinned to 0.1.2-alpha.2.
- ONLY deepseek / openai-completions and github-copilot GPT / openai-responses.
  A model appearing in a catalogue does not prove execution support or account
  entitlement. This is not arbitrary-provider support.

BUILD FROM CLONED SOURCE

No npm publication or downloadable project Release archive is assumed.
PowerShell examples follow; C:\PATH\TO values are placeholders.

  git clone https://github.com/ericzhaouu/dsh-native.git
  Set-Location .\dsh-native
  node --version
  npm.cmd ci

Confirm package.json version 0.6.0. OpenClaw is an optional peer to avoid
bundling a second production host. Development still needs the genuine SDK.
If it is absent, obtain and verify the exact official 2026.9.2 artifact from
the OpenClaw release workflow, then install it locally:

  npm.cmd install --no-save --package-lock=false "C:\PATH\TO\openclaw-2026.9.2.tgz"
  $DevHost = (Resolve-Path .\node_modules\openclaw).Path
  node .\host-patch\apply.mjs --root $DevHost --check
  npm.cmd run build
  npm.cmd pack

If the configured registry lacks that SDK, use the verified official artifact,
not speculative npm versions, a newer preview or hand-written replacement SDK
types. The check is read-only; it should report unpatched for the stock pinned
artifact. npm pack runs prepack/build and creates openclaw-dsh-native-0.6.0.tgz.
Use npm.cmd if PowerShell blocks npm.ps1; do not change execution policy.

PACKAGE ACCEPTANCE AND CI

The repository has a read-only package checker. It does not rebuild, repack or
assume a historical .tgz exists in a clean checkout; pass an explicit candidate
path when auditing a real archive:

  npm.cmd run test:package
  npm.cmd run package:check -- --package C:\PATH\TO\openclaw-dsh-native-<version>.tgz
  # optional: --expected-sha <sha256> --root C:\PATH\TO\BUILT\WORKSPACE

The checker emits JSON with the archive SHA-256 plus per-file hashes/byte counts.
It fails on hash mismatch, malformed gzip/tar/PAX data, truncation, trailing junk,
traversal, duplicate members, links, Windows-unsafe paths, unknown files, bundled
node_modules/tests/private config, credential-like content, invalid JSON, package
/ shrinkwrap root version drift, missing declared exports/OpenClaw extension/host
patch entrypoints, or bundling OpenClaw as a dependency/payload. Optional --root
compares package files to an already built workspace and rejects symlink/junction
escapes; do not use it to compare old archives with changed source trees.

Dry-run acceptance wiring is intentionally thin:

  npm.cmd run acceptance:dry-run -- --manifest C:\PATH\TO\manifest.json --run-root C:\ABS\RUNS

That forwards to scripts\run-acceptance.mjs --dry-run. The manifest format,
fixtures and live execution contract are owned by the acceptance runner.

The GitHub workflow runs only the pure Node checker fixture job by default on pull
requests across Windows/Ubuntu and Node 22.23.1/24.15.0. This isolated gate does
not build or certify the current candidate package and needs no account, publish
permission or OpenClaw SDK. Full SDK acceptance is manual dispatch only and
requires an approved OpenClaw GitHub release/artifact URL plus the pinned 2026.9.2
SHA 3431f4cd2d8dbd6b936def2694ac27e19fa0256295cf4ada0f652ecf1c9ee520. If the
artifact is missing or unavailable, the full job fails with instructions instead
of passing as skipped; without that approved URL, remote full-SDK CI remains
blocked. CI does not publish, tag, claim 1.0 readiness or run live canaries.


MAINTENANCE BEFORE INSTALL / PATCH / CONFIGURATION

Review the code, dependencies and declared capabilities. Back up configuration,
the previous plugin package and the host installation. Complete or cancel active
work and confirm tools/children have stopped BEFORE maintenance.

One Gateway serves multiple connections. Default hybrid configuration reload
can restart the shared Gateway after plugin/runtime changes, affecting
all connections, not only dsh-experiment. STOP BEFORE installation, host patching
or config edits; do not live-patch or mistake cooperative suspension for shutdown.
Use the correct installation/profile and keep its supervisor from respawning it.

  openclaw gateway stop --force
  openclaw gateway status --no-probe
  openclaw plugins install "C:\PATH\TO\openclaw-dsh-native-0.6.0.tgz" --force --accept-capabilities

The operator must verify shutdown; service status alone is not proof that all
old processes/tools have exited. For gateway stop, --force confirms a
non-interactive stop; it does not prove idle. The stop/start sequence here is for
offline installation between those steps, not an ordinary restart substitute.
For plugins install, --force acknowledges local sources/overwrite.
Official --accept-capabilities accepts declared capabilities of REVIEWED code,
not a security-policy bypass. Do not blindly accept untrusted packages.

If managed npm optional-peer reconciliation fails, do not repair it by guessing
a host version or rewriting shared host dependencies. A prepared-directory
installation is an alternative, still with Gateway stopped:

  New-Item -ItemType Directory -Path .\artifacts\prepared-dsh-native
  tar -xf .\openclaw-dsh-native-0.6.0.tgz -C .\artifacts\prepared-dsh-native
  Push-Location .\artifacts\prepared-dsh-native\package
  npm.cmd ci --omit=dev
  Pop-Location
  $PreparedPlugin = (Resolve-Path .\artifacts\prepared-dsh-native\package).Path
  openclaw plugins install $PreparedPlugin --force --accept-capabilities

Use a fresh preparation directory. It must contain built dist, manifest,
lockfile and complete target-platform runtime node_modules, not a development
copy of node_modules\openclaw. The directory install path does NOT build or
install dependencies for you. It is not equivalent to an unprepared checkout.
Keep required runtime peers from the shipped lockfile: --omit=peer would also
remove dependencies required by DSH, not just the optional OpenClaw SDK.

OPTIONAL AGENT-LEVEL SELECTION (0.3 HOST PATCH)

  agents.entries.dsh-experiment.runtime:
    type: embedded
    harness: dsh-native

runtime.harness is an explicit HOST EXTENSION, NOT a stock 2026.9.2 SDK field.
The patch is pinned to the official 2026.9.2 artifact and source commit:
  3928bad9badfcb6c7d140530435e806fb8092190

host-patch\spec.mjs fixes 12 target-file SHA-256 hashes and exact edits. This is
not a whole-release tarball checksum or validation of every host dependency.
The recorded source commit is not a substitute for artifact provenance.
Unrecognized builds/local edits fail without being overwritten.

Keep Gateway stopped. The root must be the actual Gateway's OpenClaw package
containing openclaw.mjs, package.json and dist, not user state or a bin shim:

  $HostRoot = "C:\PATH\TO\openclaw-package"
  node .\host-patch\apply.mjs --root $HostRoot --check
  node .\host-patch\apply.mjs --root $HostRoot --apply --offline-confirmed
  node .\host-patch\apply.mjs --root $HostRoot --check

--offline-confirmed is an OPERATOR ASSERTION, not automatic shutdown or Gateway
detection. The patch tool never stops/restarts/reloads/signals Gateway or edits
config. Read host-patch\USAGE.txt for receipts, partial state and restoration.

Merge examples\openclaw.agent-pinned.json only for the intended existing Agent.
Use an existing dedicated absolute workspace. Preserve default model, auth,
other Agents and security policy. If plugins.allow exists, add dsh-native
without replacing the list.

Do NOT set agents.defaults.model or an Agent model merely to select DSH.
OpenClaw resolves its normal current/default model, account, parameters and
limits. When no Agent-specific model overrides exist, normal defaults apply.
Remove ONLY that Agent's obsolete models[...].agentRuntime leaves; preserve
other fields in those entries. Do not change global model/default policies.

Model/provider runtime entries cannot override an Agent pin. Every fallback
candidate retains the same harness; unsupported routes fail with a typed
incompatibility, not a substitute model or escape to the built-in runtime.
An ACP runtime cannot carry this embedded harness field.

  openclaw plugins enable dsh-native
  openclaw gateway start
  openclaw gateway status

Use /new in the target Agent's chat/Dashboard before the next task.
Model inheritance is NOT migration of an existing native session.

STOCK HOST COMPATIBILITY

Without the optional patch, use explicit per-model agentRuntime.id instead of
runtime.harness. examples\openclaw.experiment.json and openclaw.copilot.json
illustrate that mode. Each selected model needs its own runtime entry.
The model must already be configured, selected and authenticated by OpenClaw.

examples\openclaw.enabled.json / openclaw.disabled.json affect model DEFAULTS,
not just one Agent. Do not copy them over unrelated defaults. The experiment
examples select coding/local Gateway execution and sandbox off; do not disable
a required sandbox or policy to make them run. Use the built-in runtime when
the session's requirements are incompatible.

FIRST TASK AND VERIFICATION

In a dedicated disposable workspace, create a non-secret smoke-input.txt and
ensure smoke-output.txt does not exist. In a NEW conversation ask:

  Only within this workspace, read smoke-input.txt. Stop if smoke-output.txt
  exists; otherwise use the host write tool to copy the input there, then read
  it back to verify. Do not run commands, use the network, access other
  directories or modify existing files/config/credentials. Stop on missing
  permission. Report only actual tool results.

CLI users can select a fresh key rather than reuse existing native ownership:

  $SmokeSession = "dsh-smoke-" + [guid]::NewGuid().ToString("N")
  openclaw agent --agent dsh-experiment --session-key $SmokeSession --message "Read smoke-input.txt in this workspace. Stop if smoke-output.txt exists; otherwise copy it with write and verify with read. No commands, network, other directories or existing-file changes. Stop on missing permission." --json

This uses the real model account and may incur charges. A model's self-claim,
or a particular response phrase, does not prove DSH activation. Check the actual
host runtime selection/progress, callback results, output file and local binding.
Do not publish unsanitized diagnostics. CLI --message "/new" does not invoke the
chat slash-command dispatcher; use chat /new or an explicit new session key.

MODELS / AUTHENTICATION

DeepSeek requires a concrete deepseek Chat Completions model and host-prepared
API key. Thinking off disables thinking; minimal/low/medium/high map to high;
xhigh/max map to max. Unsupported custom mappings/transport/sampling fail.

Copilot requires a concrete github-copilot gpt-* Responses model. Keep the
ordinary OpenClaw login. OpenClaw/service own account validation, tenant
discovery, entitlements and resolved endpoint. No second OAuth, token export,
DeepSeek key or OpenAI API subscription is required for that route.

Model id, context/output limits and reasoning capabilities come from OpenClaw,
not the old bundled pi-ai catalogue. off/minimal/low/medium/high/xhigh/max work
only when representable and supported by that model; adaptive, ultra and
arbitrary parameter overrides are rejected. Copilot off omits reasoning.

Allowed prepared integration/editor/organization headers are retained;
X-Initiator is computed for user versus tool-follow-up requests. DSH owns its
product User-Agent; authored custom User-Agent is rejected. This is not an
identical reimplementation of OpenClaw's HTTP stack.

Copilot native persistence strips encrypted reasoning signatures, response ids
and opaque item ids while retaining tool/result correlation. Unsigned reasoning
remains reasoning locally and is omitted by Responses replay, never changed
into assistant text. Invalid/imported unsanitized history is rejected. Trailing
reasoning whitespace is delayed until canonical closure; real rewrites fail.

CONFIGURATION DEFAULTS

Scope: plugins.entries.dsh-native.config. Unknown fields are rejected.
Authoritative definitions: openclaw.plugin.json and src\config.ts.

  stateDir              user's home + .openclaw\dsh-native; absolute path only
  startupTimeoutMs      60000
  shutdownTimeoutMs     15000
  streamIdleTimeoutMs    120000
  allowedBaseUrls       ["https://api.deepseek.com"]
  allowedCopilotBaseUrls:
    https://api.individual.githubcopilot.com
    https://api.business.githubcopilot.com
    https://api.enterprise.githubcopilot.com
    https://api.githubcopilot.com

Timeouts are integers from 100 to 3600000 milliseconds. Stream idle timeout is
not the total attempt deadline. Both endpoint lists must be nonempty and use
exact normalized URLs, not wildcards. The lists are independent. Add only a
trusted host-resolved custom tenant/data-residency HTTPS endpoint to the right
list. Credentials, query and fragment in URLs are forbidden; plaintext remote
HTTP is forbidden. Explicit HTTP loopback entries are for local fixtures only.

CAPABILITIES / DASHBOARD

Text input and text-compatible tool results only. The legacy default family is:
  read edit write apply_patch exec process grep glob find ls
Explicit toolAllowlist may additionally select compatible core/search/plugin tools.
Actual availability remains host-policy filtered; not all tools are promised.

The ONLY absent-session-tool safe-deny exceptions are:
  sessions_list sessions_history sessions_send session_status
Neither callback host nor DSH exposes these. Existing denies remain in force;
legacy runs reject other explicit native-surface restrictions before inference.
Explicit top-level narrowing retains those restrictions in host construction and
bound dispatch; it does not remove the policy or grant an ambient native tool.
Do not delete required security rules to use the experiment.

No blanket browser, requester-MCP, messaging, plugin-tool grants, subagents/delegation,
skill-library authoring, custom context engines or external compaction, migration/
fork, media, Code Mode, live steering, session permission overrides, remote/

STATE / FAILURE / SECURITY

NATIVE COMPACTION / MAINTENANCE (0.6.0)

Current source separates aggregate billed usage from the final model call's
contextUsage. SDK contextTokens is window capacity, not consumed tokens.
The Dashboard history projection may omit contextUsage; canonical raw transcript
events and attemptUsage retain the authoritative accounting fields.

Official DSH pressure compaction and public host compact() replace only the native
model-visible surface, retaining original durable events. Summary calls use the
same host-prepared model/auth and zero tools. Compaction request IDs survive later
foreground turns. A pending compact can be inspected without model/tool replay
before the next foreground attempt; partial/uncertain records and live owner locks
still fail closed. This does not recover or replay interrupted business operations.

Host memory-trigger maintenance uses a separate native binding and a bounded
canonical evidence snapshot, never a foreground user/assistant transcript pair.
Limits: 60 seconds, four host callbacks, 4096 output tokens. Only policy-admitted
read and the host's exact-target append-only write wrapper are exposed; no exec.
Earlier messages can be omitted from its explicitly labelled bounded snapshot.

runIsolatedCompletionV2 accepts host-owned prepared auth/model with strict visible
text and no tools, uses disposable private state and supports cancellation.
Harness-owned auth, temperature overrides and non-text/output-policy extensions
remain unsupported; not every title/auxiliary workflow is promised compatible.

These 0.6.0 changes require an explicit upgrade of previously installed versions.
Existing foreign-compacted or inconsistent mirrors are not rewritten/imported:
retain them for inspection and use /new. Deployment/restart remains separate.

Each host session has a hashed state directory, private DSH_HOME and binding.
A fresh child resumes native history each turn. Success flushes persistence,
drains the bridge and closes the child before making the binding reusable.
OpenClaw's mirror does not replace native DSH history.

Credentials pass only in a narrowed child environment, not argv or plaintext
plugin config/profile/binding. The child and sufficiently privileged local code
can still inspect them: this is NOT secret isolation from malicious native code.
The binding stores a route/account fingerprint, not the usable token. Only
approved non-secret request identity headers may persist; Authorization/Cookie
and arbitrary headers are rejected.

Runtime/model/provider/account/token/endpoint/request-identity/workspace or
session ownership changes require /new, not reinterpretation of an old binding.
0.1 bindings lack later model/account fingerprints and are not silently migrated.

The exclusive owner.lock prevents concurrent owners. Running/blocked bindings,
consumed attempts, uncertain outcomes and mirror/native mismatches fail closed.
There is no automatic deletion, unlock, migration or replay after a crash.
Confirm old host, child and tools have stopped, inspect possible side effects,
then start a new conversation. Do not edit binding status or delete native
history to force a retry. Reset/disable retains old state for inspection.

Private config, histories, logs, receipts, real paths/accounts/IPs/session ids
must not enter the public repository or Issues. Fingerprints are not tokens,
but the surrounding metadata is still private. Provider token counters are not
authoritative billing; zero cost means unpriced, not free inference.

DISABLE / UNPIN / RESTORE / UPGRADE

Stop active work and the shared Gateway first. To remove only the Agent pin:

  openclaw config unset agents.entries.dsh-experiment.runtime.harness

Or replace the WHOLE runtime object with {"type":"embedded"}. Merging an object
that merely omits harness does not delete it; this also applies to the unpinned
example. Unpin restores ordinary host policy, which can expose older model pins.
On the patched host, explicitly require the built-in runtime with:

  openclaw config set agents.entries.dsh-experiment.runtime.harness openclaw

auto/default are not pin values. For legacy mode, remove or change only the
intended Agent's old agentRuntime leaves, preserving other model fields.
Do not disable the plugin globally while other Agents still select DSH.

  openclaw plugins disable dsh-native
  openclaw gateway start

Use /new. Re-enabling also requires deliberate selection and a new conversation;
disabling alone does not rewrite selection or migrate bound native history.
Provider authentication stays independent; do not delete it or private state.

To restore stock host code, keep Gateway stopped and FIRST remove all added
runtime.harness fields (including "openclaw"), restoring the intended prior
configuration. Then:

  node .\host-patch\apply.mjs --root $HostRoot --restore --offline-confirmed
  node .\host-patch\apply.mjs --root $HostRoot --check

Start only after a successful unpatched check. Preserve installation-local
.dsh-agent-harness-patch backups/receipt. For partial state or patch-lock recovery
read host-patch\USAGE.txt; --recover-stale-lock is NOT a native-session unlock.

For upgrades, retain a known-good plugin archive/config, stop before reinstall,
recheck the exact host artifact and use /new. Host updates can replace patched
files; maintenance/rebasing is required. Do not apply this patch to new builds
or replace individual live JS files. 0.5.1 retains the prior streaming/delivery fixes.

TROUBLESHOOTING

- Unknown runtime.harness: stock/wrong/partially patched host; check actual root.
- Missing openclaw/plugin-sdk exports: provide exact official optional peer SDK.
- Requires explicit selection: enabled plugin alone is insufficient; use /new.
- Pinned route incompatibility: only the two documented routes work; no escape.
- Host-prepared auth failure: fix normal OpenClaw login, not plugin key settings.
- Endpoint denied: review exact URL in the provider-specific allowlist.
- Policy/non-core tool/placement rejection: keep policy; use built-in runtime.
- Changed fingerprint/ownership or missing/mismatched native history: /new.
- owner.lock/uncertain outcome/already submitted: inspect stopped owners and
  effects; do not automatically unlock or replay.
- Unconfirmed termination/startup timeout: check Node/dependencies/processes in
  maintenance; do not blindly resubmit work.
- INVALID_ARGS/HOST_TOOL_ERROR: inspect actual schema, authorization and result.
