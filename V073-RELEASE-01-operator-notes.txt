WORKFLOW CONTRACT
Required Linux: ubuntu-24.04, Node 22.23.1 and 24.15.0.
Experimental Windows: windows-2022, the same Node versions; separate jobs
and continue-on-error. Windows jobs are NOT dependencies of the Linux gate.
Action revisions are full commit pins resolved via gh REST from v4 tags.
Hosted runner images are not immutable; the OS label alone is not a fully
hermetic build environment.

PR runs execute generated package/release fixtures only, with no npm
dependency installation, SDK, provider accounts, or artifact token.
Manual workflow_dispatch additionally requires both Linux SDK matrix jobs.
The always-running Linux aggregate depends on BOTH required matrix jobs
and rejects failed/cancelled/skipped/missing required results. Its PR report
explicitly says fixtures-only and sdkAcceptance=false. A green PR is not
full SDK acceptance. This workflow never publishes a release.

Full SDK jobs validate the URL and pin before downloading. The token exists
only in the download step and is sent only to the initial official API
request, never redirects, installation, tests, or uploaded evidence.
Downloads/installations use artifacts\release-private (ignored, NOT
uploaded). Each job uses npm ci --ignore-scripts, installs the exact SDK
without lifecycle scripts, checks stock companion state, typechecks,
builds, runs npm test, rebuilds, packs twice into NEW unique directories,
compares archive hashes, then creates and verifies a clean-source manifest.
Linux full jobs explicitly set DSH_RUN_ISOLATED_SDK_TRANSPORT=1; the full driver
refuses a Linux run without it, rather than accepting a skipped transport gate.
This covers genuine SDK ingress/dedupe with private loopback model/text transport,
not actual Feishu or card fallback certification. Experimental Windows retains
the explicit Linux-only skips without relaxing its subprocess safety guard.

Uploads use an explicit filename allowlist. Only generated-suite summary,
manifest, verification, repeat-pack comparison, SHA256SUMS and gate decision
are eligible. No raw test logs, fixture transcripts/auth files, SDK archive,
product archive, broad directory/glob, or live account output is uploaded.
Artifacts last 14 days. Inspect an artifact's successful run/commit as well
as its contents; the summaries are unsigned evidence, not an attestation.

MANIFEST AND REPRODUCIBILITY CONTRACT
scripts\release-manifest.mjs create/verify require explicit --root,
--package and --expected-sha. No historic ignored .tgz is selected.
The manifest binds product hash/size/version, HEAD commit/tree, deterministic
nonignored source-byte snapshot, index/flag hashes, source status counts,
and four baseline patch bundles: agent-harness, compact-auth, source-reply,
table-policy (including their shared engine/imported spec). If the separately
reviewed group-readonly companion is present, it is also required in the
archive and gets its own hash binding. No source contents/diffs, arbitrary
paths, account state, environment dump or test secret is included.

Local mode allows dirty and nonignored untracked packaged source. Release
mode requires clean tracked source. Ignored non-dist package source,
unsafe links/submodules/output paths, hidden index flags, missing companions,
wrong pins, source/archive drift and manifest tampering fail closed.
Outputs inside the repo must be ignored/untracked, not source/input aliases.

source.releaseReady means SOURCE cleanliness only, not approval to publish.
The SDK hash in the manifest is a declared requirement, not proof of SDK
download/install; full-sdk-results adds the local pinned-SDK test outcome.
verify re-audits against the actual checkout/build/artifact. Its snapshot
is byte-sensitive: another checkout with CRLF/LF differences can differ.
reproducibility.json compares two fresh npm packs of ONE built workspace;
it does NOT claim independent rebuilds or cross-platform identical archives.
No compiler provenance, digital signature or real-account success is claimed.
